# Prep LMS CRM 운영 안내

## 매일 확인할 곳

1. **대시보드 > 지금 확인할 사항**: 지연 업무, 정기 연락 경과, 학부모 제출 자료,
   요청 자료 회신, 프로그램 종료와 원서 마감 누락을 확인합니다.
2. **학생 관리**: 학생명·학교·관리 태그를 검색합니다. 관리 상태와 정렬은 바로
   선택하고, 담당자·프로그램·Stage·우선순위·확인 사항은 상세 필터에서 선택합니다.
   자주 쓰는 조건은 '내 필터 보기'에 저장합니다. 다른 직원에게는 공유되지 않습니다.
3. **CRM 관리 > 통합 업무**: 원래의 학생 업무, EC 목표 마일스톤, 원서 준비 항목을
   함께 확인하고 수정합니다. 별도의 복사본을 만드는 것이 아닙니다.
4. **학생 상세 > 연락 / 관리**: 연락 이력, 내부 인수인계 메모, 정기 연락 주기,
   체크리스트와 학부모 안내 초안을 관리합니다.

## 연락과 후속 업무

- 연락 대상, 수단, 결과, 날짜와 내용을 기록합니다. 후속 업무와 기한을 함께 입력하면
  담당자 할 일과 캘린더에 자동으로 연결됩니다.
- '연락 완료' 또는 반영 완료된 미팅만 최근 연락일로 계산합니다. 연락 시도나
  회신 대기는 정기 연락 주기를 초기화하지 않습니다. 기록이 없다는 이유만으로
  지연되었다고 단정하지 않습니다.
- 저장한 연락 이력은 덮어쓰지 않습니다. 수정할 사실이 있으면 새 정정 기록을 남깁니다.
- 안내 초안은 검토하고 복사할 수 있습니다. 이메일·문자·KakaoTalk 자동 발송은 하지 않습니다.
  진행상황 초안에는 이미 공개 승인된 요약만 사용합니다.

## 자료 요청과 회신

1. 담당자가 **학생 상세 > 자료 요청**에서 자료명, 종류, 기한과 안내를 등록합니다.
   해당 학생의 학부모 포털이 먼저 활성화되어 있어야 합니다.
2. 연결된 학부모는 **요청 자료**에서 자료 링크 또는 답변을 제출합니다.
3. 담당자의 확인 목록에 검토 대기로 표시됩니다. 확인 완료 또는 보완 요청을 선택합니다.
   보완 요청에는 사유가 필수입니다.
4. 학부모가 다시 제출하면 이전 답변을 보존하고 새 회신을 추가합니다.
   서버가 실제 검토자와 시각을 기록하며 검토 이력도 보존합니다.

요청 기한은 직원·학생 캘린더에 표시되고 누르면 자료 요청으로 연결됩니다.
회신을 확인 완료해도 시험 점수나 성적표 내용이 자동 확정되지는 않습니다.
현재 첨부 방식은 안전한 HTTP(S) 링크입니다. 원본 파일 업로드, 외부 OCR, 외부 AI
전송은 하지 않으며 링크 파일의 접근 권한은 별도로 확인해야 합니다.

## 일괄 작업과 인수인계

- 학생 목록에서 대상을 선택한 뒤 동일 업무를 학생별로 등록할 수 있습니다.
  1회 최대 100명이며 선택한 학생만 변경됩니다.
- 담당자 교체는 관리자만 할 수 있습니다. 새 담당자와 접근 권한 변경을 확인해야 합니다.
- 제외되는 담당자의 미완료 업무를 새 첫 번째 담당자에게 함께 넘길 수 있습니다.
  이전 완료 업무의 담당자, 연락 기록, 보고서 작성자는 변경하지 않습니다.
- 담당자별 업무 현황은 관리 학생, 공동 관리, 미완료, 지연, 7일 내 업무를 구분합니다.
  공동 관리 중 업무 담당자가 따로 없는 항목은 각 담당자의 확인 대상으로 집계합니다.
- 중복 가능 학생은 이름과 생년월일이 모두 같을 때 안내할 뿐 자동 병합·삭제하지 않습니다.

## 관리 종료와 권한

CRM 상태(관리 중 / 일시 중지 / 관리 종료)는 Stage 1~5와 별개입니다.
관리 종료는 삭제가 아니며 학생 목록 필터로 다시 열거나 재개할 수 있습니다.
종료 학생의 업무는 대시보드와 통합 업무 기본 목록에서 제외합니다.
통합 업무의 '종료 학생 업무 포함'으로 과거 업무를 조회할 수 있습니다.

관리 종료만으로 학부모 계정을 차단하지 않습니다. 자료 접근을 막아야 한다면
학부모 포털 활성화를 끄거나 계정 관리에서 접근을 중지해야 합니다.

컨설턴트는 배정된 학생만, 학부모는 연결된 자녀와 승인된 공개 자료만 볼 수 있습니다.
CRM 연락 메모, 내부 인수인계, 직원 개인 필터와 업무는 학부모에게 전달하지 않습니다.

## 저장과 배포

- 학생 CRM: `student.operations.crm` (기존 학생 필드 보존).
- 후속 업무: 기존 `student.tasks`, 마일스톤과 원서는 원본 항목을 갱신.
- 자료 요청: `student.parentPortal.requests` (회신·검토 이력 포함).
- 개인 필터: `prep_workspaces.payload.crmViews`.
- 신규 테이블이나 데이터 이전은 필요하지 않습니다. 기존 학생은 기본 '관리 중'으로 해석합니다.
- 낡은 브라우저가 저장해도 기존 CRM 연락 이력과 요청 자료를 서버가 보존합니다.
- 버전 충돌은 덮어쓰지 않고 새로 불러오도록 안내합니다.
- 주기적인 변경 확인은 보고서 본문 대신 접근 가능한 레코드의 버전만 조회합니다.

프런트엔드와 함께 `prep-portal` Edge Function의 `service.mjs` 및
`platform/parent-portal-model.js`를 `model.js`로 묶어 배포해야 합니다.
기존 custom `auth.getUser()`와 실제 회원 권한 검증은 그대로 유지합니다.

## 검증

```powershell
node --test --test-isolation=none tests/*.test.cjs
node tests/crm-browser.cjs http://127.0.0.1:8765/platform/index.html
node tests/operations-browser.cjs http://127.0.0.1:8765/platform/index.html
```

브라우저 검증은 API를 격리한 가상 계정·학생으로 진행하며 실제 학생 자료를 변경하지 않습니다.
배포 후에는 Vercel 주소로 같은 검증을 실행하고, 실제 Edge API의 익명·위조 토큰 차단을
별도로 확인합니다. 실제 로그인 사용자 전체의 데이터 이동을 재현하는 테스트는 아닙니다.
